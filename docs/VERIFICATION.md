Not validated: production hosting, university SSO/MFA, university finance or facilities data, formal accessibility certification, tagged PDF accessibility, USG reporting compliance, high-load behavior, backup restoration or institutional approval. ## Startup repair validation

The development container now runs a foreground supervisor as its main process rather than a detached post-start shell command. The supervisor binds the forwarded port immediately, shows startup progress, waits for the database, installs dependencies when needed, migrates, and proxies to Next.js after a database-backed health check. The exact Codespaces hostname is permitted for Next.js development assets while application origin checks remain enforced.

Validated locally: browser sign-in and dashboard through the supervisor, PDF/Excel exports, mobile overflow, rejection of an untrusted origin, duplicate-start detection, and a missing-database simulation that keeps the port open on a branded progress page without exposing credentials. A separate smoke test exercised a simulated Codespaces HTTPS origin and session cookie through the proxy. Seven database integration tests and production compilation/type checks pass.

The actual user's Codespace cannot be accessed or rebuilt by the available tools. A full dev-container reproduction in this managed executor was limited by disk space during Docker image/container creation; this is not proof of the user's failure cause. Docker Compose configuration was validated, and supervisor/application behavior was tested directly against PostgreSQL. Applying this change to an existing Codespace requires pulling main and rebuilding its container; creating a new Codespace uses the updated startup configuration automatically.
