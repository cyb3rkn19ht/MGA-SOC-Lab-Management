# MGA School of Computing Laboratory Management

Local full-stack Next.js / React / TypeScript application with PostgreSQL, preserving the supplied purple university prototype. All seeded inventory, personnel, facility values and costs are **fictional and unverified**. No university systems are connected. No public deployment has been performed.

## Open the application in your browser

[Create a GitHub Codespace](https://codespaces.new/cyb3rkn19ht/MGA-SOC-Lab-Management?quickstart=1) for this repository. GitHub may apply Codespaces usage limits or charges; creating the environment remains your action.

The included dev container starts PostgreSQL, installs dependencies, runs migrations with fictional seed data, and starts a supervised preview on port 3000. A purple startup page shows progress until the application is ready. Open the **Ports** tab and choose **Open in Browser** for port **3000**. Keep the forwarded port **Private**. The preview process configures the exact forwarded HTTPS origin and secure cookies automatically. Sign in with the demo accounts below. This is a development preview; it does not publish a production university service.

If the browser does not open automatically, inspect `/tmp/mga-next.log`. The container owns the preview process, so it survives terminal closure. To restart it, use **Codespaces: Rebuild Container**. Running `npm run preview` again reports whether the existing preview is already running without starting a duplicate. Changing the forwarded host requires restarting the container so its permitted origin matches. A `localhost:3000` link on your own computer cannot reach a separate cloud workspace without port forwarding.

## Apply the startup fix to an existing Codespace

In the Codespace terminal run `git pull --ff-only origin main`, then open the command palette (**Ctrl+Shift+P**, or **Cmd+Shift+P** on Mac), choose **Codespaces: Rebuild Container**, and confirm the rebuild. This updates the container command; refreshing the page alone does not apply container configuration changes. Existing database volumes are preserved. Once the Codespace reopens, open **Ports → 3000 → Open in Browser**. Keep the port private. The startup page refreshes automatically until the sign-in page is ready.

The preview binds port 3000 on all interfaces and starts Next.js on an internal loopback port. It waits for PostgreSQL, applies migrations and installs missing dependencies before forwarding requests. Startup failures appear as a status page rather than an unexplained disconnected port. Next.js allows only the exact Codespaces hostname for development assets; API origin checks and secure session cookies remain enabled.

## Install and run

Requires Node.js 22.21+ (tested with 24.22), npm and Docker Compose v2, or PostgreSQL 17.

```sh
node scripts/configure-local.mjs
npm ci
# Starts only the local database; binds PostgreSQL to loopback.
docker compose up -d db
# Wait for the database healthcheck to pass.
npm run db:setup
npm run dev
```

Open http://localhost:3000. Set APP_ORIGIN to the exact browser origin, including port, before starting the server. Different localhost/127.0.0.1 names count as different origins. This check protects writes from cross-origin requests.

The migration account needs database owner and CREATE ROLE privileges for initial local setup. Runtime connections use `mga_app`, not the migration owner. Example files contain placeholders; the setup script generates unique local credentials. For a managed database, have the DBA provision a restricted runtime role and adapt the role-creation statement; rotate the runtime password in both PostgreSQL and DATABASE_URL. Do not give the web server MIGRATION_DATABASE_URL in a production environment.

Initial accounts (all share DEMO_PASSWORD from .env; a unique password is generated by `scripts/configure-local.mjs`; read DEMO_PASSWORD in your local ignored `.env`):

| Email | Role |
| --- | --- |
| admin@demo.invalid | System Administrator |
| school@demo.invalid | School Administrator |
| manager@demo.invalid | Laboratory Manager |
| assistant@demo.invalid | Laboratory Assistant |
| faculty@demo.invalid | Faculty/Staff |

Manager and assistant are assigned to Digital Forensics. Administrators see all labs; managers and assistants see assigned labs; faculty can read and request purchases. Use User Administration to create local accounts, assign roles/labs and deactivate accounts. Privilege changes revoke the affected sessions. The current administrator cannot modify their own privileges. Password resets and institutional identity lifecycle integration require the production identity design described below.

## Reset demo administrator access

Run `npm run demo:reset-admin` in the Codespace terminal. It resets `admin@demo.invalid` to the generated DEMO_PASSWORD in the local ignored `.env`, reactivates the fictional demo account, clears its failed-login lockout and revokes its sessions. The sign-in email and password print only in that terminal. Refresh the sign-in page and use those details. The command requires the local migration database connection; it does not reset institutional accounts or publish passwords.

## Working stages

1. **Design and model** — [design specification](docs/DESIGN.md), [architecture/schema](docs/ARCHITECTURE.md); original HTML retained in `prototype/index.html`.
2. **Dashboard and labs** — authenticated workspace; facilities, capacity, personnel, creation/edit/archive; responsive purple header/sidebar and KPI panels.
3. **Inventory and purchasing** — add/edit/archive catalog, consumable usage, durable checkout/return, loss/damage/retirement, transfers, immutable audit; independent purchase approval, PO placement, partial delivery and idempotent receipt posting.
4. **Reporting and verification** — PDF and Excel generation, scope/period filters, facilities, personnel, inventory, acquisition estimates, period transactions, purchase requests, actual recorded receipt expenditures, pending requests and discrepancies.

For a purchase: create a catalog item with zero opening quantity; request it as manager/faculty or an administrator; sign in as a different administrator to approve; place the order with a PO reference; receive a partial or full quantity with a delivery reference. Stock updates automatically. Never post a manual purchase adjustment for the same delivery. Retries use the receipt form's idempotency key. Closed/overreceived purchases are rejected. Monetary values are recorded in USD. Request estimates are separate from actual recorded receipts, which remain unreconciled with university finance.

Returns require the original checkout and cannot exceed its outstanding quantity. Transfer source and destination both require authorization; administrators can perform transfers between independently managed labs. Damage removes units from service. Corrections are new ledger transactions with a reason; historical rows cannot be edited or deleted. Item definitions are global catalog entries, so only administrators edit existing definitions. Lab staff can create new catalog entries and transact within assigned labs.

## Test and build

```sh
npm test
npm run build
npm start
```

`npm test` creates a uniquely named temporary PostgreSQL database using MIGRATION_DATABASE_URL, migrates/seeds it, runs integration tests against the restricted runtime role, and drops it afterward. The migration account requires CREATEDB. It never runs test writes against your demonstration database. Tests cover concurrency, nonnegative stock, authorization including direct SQL policy enforcement, transfer conservation, immutable history, independent purchase approval, partial receipts/replays/overreceipt, return reconciliation and serialized assets.

Browser QA can run with the application on port 3000 and the original prototype served on port 3001:

```sh
python -m http.server 3001 --directory prototype --bind 127.0.0.1
# In another terminal, with the app running:
npm run test:browser
```

Uses `/usr/bin/chromium`, or set CHROMIUM_PATH to another installed Chromium. Screenshots and sample reports are saved to `work/qa/`. Browser tests use the seeded administrator account and DEMO_PASSWORD. Do not run browser QA against real university data.

A supervised preview can also be started with `npm run preview` after local database setup. Run `npm run test:preview` in another terminal to verify readiness, login, authorization origin checks and PDF/Excel exports.

## Reports and dates

Executive Report offers lab/school scope, custom dates, spring/summer/fall semester, academic year and fiscal year. Fiscal year is selected by ending year (July–June); academic year starts August; semester bounds are planning defaults, **not certified MGA calendars**. Validate calendar definitions before official use. Dates filter transactions, requests and receipt expenditure; facilities/current stock remain current snapshots. Acquisition values use recorded unit cost and are estimates, not GAAP book values. Missing fields are marked missing/unverified. Reports make no USG compliance claim.

## Configuration and operations

- DATABASE_URL: restricted runtime PostgreSQL connection; TLS required outside a trusted local environment.
- MIGRATION_DATABASE_URL: owner connection for the migration CLI only.
- APP_ORIGIN: canonical permitted browser origin.
- DEMO_PASSWORD: seed password of at least 16 characters. Only used when seeding an empty database.
- COOKIE_SECURE: `false` only for local HTTP; use `true` with HTTPS.

Migrations 001–003 are versioned in `db/`, applied transactionally with an advisory lock. Existing versions are not rerun. Back up a database before future schema changes. `docker compose down` stops the local database; data persists in its named volume. Do not delete the volume unless intentionally discarding the demonstration database.

## Production deployment — approval required

This is a tested local development application, not an approved institutional service. Before any hosting, production data import, identity connection or financial integration, obtain the approvals in [PRODUCTION.md](docs/PRODUCTION.md). After approval: build with `npm ci && npm run build`; provision managed PostgreSQL and restricted credentials; apply migrations through an approved one-time job; run `npm start` behind an HTTPS reverse proxy; configure origin, secure cookies, backups, monitoring and network controls. Do not seed fictional accounts in production. The current setup CLI intentionally seeds an empty local database; split migrations from seed and use an approved bootstrap administrator process for production. No production deployment credentials or infrastructure are included.

### Sign-in returns HTTP 403 in Codespaces

A 403 at `/api/login` means the origin check rejected the browser address before password validation. Current code automatically recognizes the exact forwarded origin for CODESPACE_NAME, independently of a stale localhost APP_ORIGIN. It does not allow arbitrary forwarded hosts or all Codespaces.

For an immediate restart of an older checkout, stop the running server with **Ctrl+C** so the shell prompt is visible, then run:

```sh
APP_ORIGIN="https://${CODESPACE_NAME}-3000.${GITHUB_CODESPACES_PORT_FORWARDING_DOMAIN:-app.github.dev}" COOKIE_SECURE=true npm run dev -- --port 3000
```

Refresh the forwarded port-3000 sign-in page after the server says Ready. Password-reset commands only execute at the shell prompt; typing them while the server is running sends text to the server process instead.
